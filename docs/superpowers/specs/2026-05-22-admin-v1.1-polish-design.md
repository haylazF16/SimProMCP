# Admin v1.1 polish — design

> Status: design approved (2026-05-22). Next: implementation plan.

## Why

Three pieces of feedback after shipping the v1.0 usage dashboard:

1. **Audit log lacks specificity.** Rows say "Viewed purchase order" but not WHICH purchase order. The data is already captured server-side (the `details` field via `summarizeArgs` in `server.ts`) — it's just not surfaced in the UI.
2. **No way to navigate "home" via the logo.** Standard expectation on any admin tool: click the brand mark in the top-left to return to the dashboard. Currently the only way to get back to `/admin` is via the nav links, which feels less polished than every web app the user has used elsewhere.
3. **Usage dashboard feels premature and not functional.** Flat tiles, static charts, no drill-down. User wants to click a user row to see that person's full pattern, plus a time range picker so they can scope the charts and per-user table to any window.

## Scope

**In:**
- Audit log row shows the inline detail when present.
- Header bar with clickable logo on every admin page.
- Usage dashboard visual refresh (Stripe-clean style).
- Per-user drill-down at `GET /admin/usage/:userName`.
- Time range picker (today / 7d / 30d / 90d / custom) scoping charts + per-user table on both the overview and the drill-down.

**Out (explicitly deferred):**
- Hover tooltips on charts (beyond the existing `<title>` element).
- Week-over-week deltas / sparklines in KPI tiles.
- Real-time refresh / auto-polling.
- Per-tool drill-down (`/admin/usage/tools/:toolName`).
- Activity heatmap (GitHub-style grid).
- Time range applying to the always-on KPI tiles (Today / 7d / 30d / Active users today stay fixed).

## Decisions locked

- **Visual direction:** "Stripe-clean" — light theme, white cards with subtle shadows, brand-blue accents, soft green for healthy / amber for warning indicators. Larger KPI numbers, better typography.
- **Range picker scope:** Charts + per-user table only. The 8 KPI tiles keep their fixed windows (Today / 7d / 30d / Active users today / Fail rate 7d / Peak req/sec 1h / 429s today / Local rate-limit hits today).
- **Drill-down auth:** Same `requireAdmin` as the rest of `/admin/*`. No coworker-self-service in v1.1.
- **Logo:** User will supply an image asset (PNG or SVG). Served via `GET /admin/static/logo.<ext>`, admin-gated (the file shouldn't leak via the public Funnel without auth).

## Components

### 1. Audit log — inline detail

**File:** `src/http/admin-templates.ts`.

The audit page parser already produces a `ParsedAuditRow`. Today the type omits the captured `details` field. Add it:

```ts
interface ParsedAuditRow {
  // ...existing fields...
  details?: string;
}
```

In `parseAuditLines`, accept `details` from the JSON. In the row render, replace this:

```ts
<td>${esc(action)} <span class="raw" title="${esc(r.tool)}">·</span></td>
```

with this:

```ts
<td>
  ${esc(action)}${r.details ? ` <span class="detail">${esc(r.details)}</span>` : ""}
  <span class="raw" title="${esc(r.tool)}">·</span>
</td>
```

CSS for `.detail`: small, muted grey, tabular-nums where applicable.

Old entries (pre-`summarizeArgs`, recorded before May 14 2026) simply have no `details` field — they render as before. Graceful degradation, no migration.

### 2. Logo + header bar

**Files:** `src/http/static/logo.<ext>` (new, user-supplied), `src/http/server.ts` (new static route), `src/http/admin-templates.ts` (new `HEADER` constant; `NAV` repurposed under it).

#### Logo asset
- User supplies a PNG or SVG. Place it at `src/http/static/logo.svg` (preferred) or `.png`. Add to git.
- Recommended max height 40 px to fit the header bar.

#### Static route
In `server.ts`, mount a small Express handler at `/admin/static/:file`:

```ts
app.get("/admin/static/:file", requireAdmin(config.SIMPRO_TOKENS_FILE), (req, res) => {
  const allowed = new Set(["logo.svg", "logo.png"]);
  if (!allowed.has(req.params.file)) { res.status(404).end(); return; }
  res.sendFile(path.join(__dirname, "static", req.params.file));
});
```

Why admin-gated: the logo isn't sensitive, but every other `/admin/*` route is auth-gated and we want a consistent surface. Bonus: prevents bots crawling the Funnel from grabbing the asset.

#### Header bar
A new `HEADER` constant in `admin-templates.ts` replaces the current `<h1>` style and includes the logo + page title + the existing nav links + logout. Every render function (`renderDashboard`, `renderAuditView`, `renderUsageView`, `renderManualCreatePage`, `renderUserUsageView`) substitutes `${renderHeader("Page title", adminName)}` at the top of `<body>`.

```ts
function renderHeader(pageTitle: string, adminName: string): string {
  return `<div class="header">
    <a href="/admin" class="brand">
      <img src="/admin/static/logo.svg" alt="Goldman" height="32">
    </a>
    <div class="page-title">${esc(pageTitle)}</div>
    <div class="header-spacer"></div>
    <nav class="nav-links">
      <a href="/admin">Users</a>
      <a href="/admin/audit">Audit log</a>
      <a href="/admin/usage">Usage</a>
      <a href="/admin/users/new">Create user</a>
    </nav>
    <form method="POST" action="/admin/logout" class="logout-form">
      <button type="submit">Logout</button>
    </form>
    <div class="header-user">${esc(adminName)}</div>
  </div>`;
}
```

The old `NAV` constant goes away (folded into `renderHeader`).

### 3. Dashboard polish — Stripe-clean visual refresh

**File:** `src/http/admin-templates.ts` (`renderUsageView` only).

CSS-only refresh. No structural HTML changes beyond what tasks 4 + 5 below introduce.

Style targets:
- `.kpi` cards: white bg, 1 px border `#e5e7eb`, shadow `0 1px 3px rgba(0,0,0,0.04)`, padding 18 px, border-radius 8 px.
- `.kpi-value`: font-size 32 px (was 24 px), weight 700, color `#0f4c75`.
- `.kpi-label`: font-size 11 px, uppercase, letter-spacing 0.06 em, color `#6b7280`.
- `.kpi-sub`: font-size 11 px, color `#9ca3af`.
- Health indicators on Fail rate, 429s, Peak req/sec tiles: soft green `#10b981` if zero/healthy, amber `#f59e0b` if warning, red `#ef4444` if critical. Already partially implemented via `peakSub`; extend the pattern.
- Page background: `#f9fafb` (was `#f5f7fa` — a touch lighter).
- Cards inside `.chart`: same treatment as `.kpi`.
- Table: cleaner row hover (lighter grey), border-radius 8 px on the container, dropped heavy box-shadow in favor of border.

The three SVG charts are unchanged in structure. `renderBarChart` gets a small tweak: bars use a softer blue `#1b5e9c` instead of brand `#0f4c75` (more comfortable against the bright white background).

### 4. Time range picker

**Files:** `src/http/usage.ts` (already accepts the date input), `src/http/usageRoute.ts` (parses range param), `src/http/admin-templates.ts` (picker UI + per-user table column shape).

#### Range param
URL: `?range=today|7d|30d|90d|custom&from=YYYY-MM-DD&to=YYYY-MM-DD`.
- `range` defaults to `30d` (matches the current implicit window).
- When `range=custom`, `from` and `to` are required.
- Invalid combinations fall back to `30d`.

#### Picker UI
A button-group at the top of the page above the KPI tiles:

```html
<div class="range-picker">
  <a href="/admin/usage?range=today"  class="r-btn ${active==='today'?'on':''}">Today</a>
  <a href="/admin/usage?range=7d"     class="r-btn ${active==='7d'   ?'on':''}">7d</a>
  <a href="/admin/usage?range=30d"    class="r-btn ${active==='30d'  ?'on':''}">30d</a>
  <a href="/admin/usage?range=90d"    class="r-btn ${active==='90d'  ?'on':''}">90d</a>
  <a href="/admin/usage?range=custom" class="r-btn ${active==='custom'?'on':''}">Custom…</a>
  ${active==='custom' ? customRangeForm : ""}
</div>
```

Custom-range form is the same date-range form already on `/admin/audit`. Reuse the markup.

#### Aggregator changes
`computeUsageStats` already takes `opts.now` and a 90-day-fixed load window. Replace the implicit windows with explicit cutoffs derived from the picked range:

```ts
export interface ComputeOpts {
  now?: number;
  truncated?: boolean;
  rangeMs?: number;          // NEW: width of the picked range, defaults to 30d
}
```

When `rangeMs` is provided:
- Hour-of-day, day-of-month, day-of-week buckets all use the same `now - rangeMs` cutoff.
- Per-user table columns: **Name / Calls (in range) / Last seen / Fail rate (in range) / Top tool (in range)**.
- `last seen` deliberately stays **unbounded** — it's the most recent activity ever, even if outside the picked range. Otherwise a user who's been silent for 8 days would show "never" under a 7d range, which is misleading.
- `fail rate` and `top tool` recompute within the picked range. If the range yields zero calls for a user, fail rate is `—` and top tool is `—`.
- KPI tiles ignore `rangeMs` — they keep their fixed Today/7d/30d semantics.

#### Per-user table shape change

Current columns: Name / Today / 7d / 30d / Last seen / Fail rate / Top tool (7 cols).

New columns: **Name / Calls / Last seen / Fail rate / Top tool** (5 cols), where "Calls" is the count in the picked range.

This is a real behavior change but it matches the user's mental model: "show me last 7d" → table reflects 7d.

### 5. Per-user drill-down

**Files:** `src/http/usageRoute.ts` (new route), `src/http/admin-templates.ts` (new `renderUserUsageView`), `src/http/usage.ts` (small filter helper).

#### Route
```ts
router.get("/admin/usage/:userName", admin, handleUserUsageGet(config));
```

Handler decodes `req.params.userName`, loads the same audit history as the overview, filters to that user, runs `computeUsageStats` on the filtered set with `knownUsers: [userName]`. If the user isn't found in any audit line AND isn't in `tokens.json`, return 404.

#### Page contents (in order)
1. **Identity strip** at the top: name, badges for companies they have access to (plumbing / energy), last seen relative time. Pulled from `tokens.json` if enrolled, falls back to audit-only if revoked.
2. **Range picker** — same control as the overview, persists via query string.
3. **8 KPI tiles** scoped to this user (same shape as overview but using the user's slice — `s.totals` becomes the per-user totals, etc.).
4. **Top 10 tools** as a small ranked list with counts.
5. **Three time-pattern charts** (hour-of-day, day-of-month, day-of-week) scoped to this user + range.
6. **Recent activity feed** — last 50 audit rows from this user **within the picked range** (if the range yields fewer than 50, show all of them; if more than 50, show the newest 50). Same row format as the audit log (including the new inline `details`).
7. **"← Back to overview"** link.

#### Linkability
On the overview's per-user table, wrap each user-name cell in `<a href="/admin/usage/<encoded-name>">`. URL-encode the name (safe for spaces and most chars). Ghost users (in audit log but not enrolled) are also linkable — the drill-down works for them.

## Data flow

```
GET /admin/usage[?range=...]
  ├─ parse range param (default 30d)
  ├─ readRange(audit.log, now-90d, now, 50k)   // unchanged
  ├─ loadTokens(tokens.json)                    // unchanged
  ├─ computeUsageStats(lines, knownUsers, { now, truncated, rangeMs })
  └─ renderUsageView(adminName, stats, now, rangeParam)

GET /admin/usage/:userName[?range=...]
  ├─ parse range param (default 30d)
  ├─ decode userName
  ├─ readRange(audit.log, now-90d, now, 50k)
  ├─ loadTokens(tokens.json) → lookup userName (or fall back to audit)
  ├─ filterRowsByUser(lines, userName)          // tiny new helper
  ├─ computeUsageStats(filteredLines, [userName], { now, truncated, rangeMs })
  └─ renderUserUsageView(adminName, userMeta, stats, now, rangeParam)
```

## Open questions / honest caveats

- **Logo asset isn't in scope of the design — user supplies during implementation.** If they don't deliver one we fall back to a wordmark (text "Goldman Plumbing" in brand blue). I'd rather flag this than block.
- **"Calls (in range)" sort order:** the spec says sort by this single column descending. The fall-back tiebreaker (alphabetical by name) carries over from v1.0.
- **The `details` field currently captures only a fraction of arg shapes.** For now we display whatever's there; if it turns out search calls without IDs produce empty details, we'll extend `summarizeArgs` in a follow-up — not in this scope.

## Roll-out
